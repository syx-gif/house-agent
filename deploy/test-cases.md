## 二、推荐主流程（intent = recommend_house）

| 编号 | 输入 | 预期结果 |
|---|---|---|
| RC-01 | `帮我找西安雁塔区、预算3000以内的两室一厅` | **不触发追问**，直接出房源（该区约 79 条，必然有结果） |
| RC-02 | `帮我推荐房子` | **中断追问**，要求提供"城市"和"预算范围" |
| RC-03 | 接 RC-02 回复 `西安，预算2000到3000` | 用补充信息继续推荐，不再重复追问 |
| RC-04 | 接 RC-02 回复 `不提供` | 用默认值走通：城市=随机城市、预算 500-5000、推荐 5 套 |
| RC-05 | `给我推荐深圳2000以内的房子` | 只给上限 → 内部 `budget_min=0, budget_max=2000`，能出结果 |
| RC-06 | `帮我找上海3000以上的房子` | 只给下限 → `budget_max` 按 10000 处理 |
| RC-07 | `给我推荐3套成都的房子，预算1500-2500` | 结果**恰好 3 条**（LIMIT 3），且都在成都、价格区间内 |
| RC-08 | `帮我找西安带阳台、近地铁的房子` | 特殊要求落到 `intro`/`devices` 模糊匹配，返回房源提到阳台/地铁 |
| RC-09 | `帮我找朝南的两室一厅，深圳，预算3000以内` | 朝向映射到 `position='south'`，居室映射到 `rooms='two'` / `house_type LIKE '%2室%'` |
| RC-10 | `我要合租的房子，广州，预算1000-2000` | `rent_type` 命中合租类；若返回 0 条要检查映射（合租仅 155 条，属稀缺） |
| RC-11 | `我要整租的房子，北京，预算5000-8000` | ⚠️ **重点**：数据里整租存在 `whole`(1623) 与 `whole_rent`(1770) 两套值，若只查 `whole` 会漏掉一半 |
| RC-12 | 多轮：先说 `推荐房子` → 答 `杭州` → 再补 `预算3000以内` | 两轮信息**合并**，最终用"杭州 + 3000以内"查询 |
| RC-13 | 同一 user_id 先问 `西安2000-3000`，再新开会话问 `西安1500以内的` | 历史偏好被读到，且最低预算**更新为更低值 1500**（偏好只扩大不缩小） |

## 七、写用例时发现的两个数据风险（建议单独验证）

1. **`rent_type` 双值混用**：`whole`(1623) 与 `whole_rent`(1770) 并存，而 `recommend.py` 的提示词只把「整租」映射为 `whole`。→ 用 RC-11 验证，若结果明显偏少，说明漏查了 `whole_rent` 那 1770 条。
2. **区域后缀不统一**：北京存 `朝阳`、西安存 `雁塔区`。→ 用 ED-02 验证，带不带"区"的命中率会不同。
